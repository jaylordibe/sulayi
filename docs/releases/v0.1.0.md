# v0.1.0 — release notes

First public release of Sulayi.

---

## What this is

A local-first penetration testing tool for applications you own. Point it at your running
app, give it test accounts, and it attacks the app the way an outsider would — then reports
only what it could verify, and states plainly what it did not test.

```bash
go install github.com/jaylordibe/sulayi/cmd/sulayi@v0.1.0
sulayi attack http://localhost:3000
```

A single binary on your machine. No account, no cloud service, no AI required.

## What it tests

- **Missing authentication** — routes your specification or declared access policy marks
  protected, served to anonymous callers.
- **Broken object-level authorization (BOLA/IDOR)** — one account reading or changing
  another's records. Sulayi creates a record as each test account through your API, has the
  others try to reach it, and deletes it afterwards, checking that it is gone.
- **Broken function-level authorization** — routes only some roles should read, read by
  another role (GET only).
- **Injection and misconfiguration in GET query and path parameters** — boolean SQL
  injection, reflected XSS, template injection, open redirect, credentialed CORS and
  stack-trace disclosure, each confirmed by an observation that cannot happen by chance.

It signs in through your application's own login (bearer token or cookie session with
CSRF), finds the surface from an OpenAPI document, framework adapters (Laravel, NestJS), a
browser recording or a bounded crawl, and re-runs any finding from its recipe with
`sulayi verify <finding>` to tell you whether your fix worked.

## How it was measured

Before this release Sulayi was run against OWASP crAPI and OWASP Juice Shop at pinned
versions, three times each, and scored against ground truth written from their source
before any run ([results](../evaluation/mvp-measurement.md#entry-2--2026-11-27-commit-117d79d),
[method](../adr/0025-mvp-measurement-method.md)):

| | crAPI | Juice Shop |
|---|---|---|
| Planted defects confirmed, of those in classes Sulayi tests | 4 of 4 | 1 of 6 |
| False positives | 0 of 5 | 0 of 2 |
| Identical results across three runs | yes | yes |
| Requests outside scope | 0 | 0 |

Seven findings on two applications is too small a sample to claim a general
false-positive rate. Detection depends on the surface Sulayi is given: crAPI's
specification exposed every assessed defect, while Juice Shop's five unreached ones were
missing from the browser recording or needed an ownership rule the configuration did not
declare. Both reference starters ran with no findings and nothing left behind.

## Safety

Every request goes through one HTTP client that enforces scope, impact and budget on the
request itself.

- **The URL you pass is the authorization you grant.** Sulayi contacts that origin and
  nothing else unless you widen scope. Redirects are never followed; cloud metadata
  addresses are always denied.
- **Profiles.** `safe` changes nothing. `standard` (the default) sends only the record
  creations you declare and the deletion of exactly what it created. `aggressive` needs a
  target declared disposable and a typed confirmation of its origin.
- **Limits and audit.** 1,000 requests and 30 minutes by default; every request — sent or
  refused — is a redacted line in `requests.jsonl`.
- **Credentials** come from a git-ignored `--env` file, never from `sulayi.yaml`, and are
  sent only to the target's own origin.

Test only applications you own or are explicitly authorized in writing to test.

## Current limitations

- Injection is tested in GET query and path parameters only, never in request bodies.
- Cross-role comparison uses GET only; there is no tenancy testing.
- Not tested: SSRF, mass assignment, client-side (DOM) XSS, token forgery, business logic.
- A single-page application's API is found only from a browser recording; there is no
  headless browser.
- OAuth authorization flows, OIDC, MFA and browser login are not supported.
- Framework adapters read source statically and cover Laravel and NestJS only.
- **Nuclei and ZAP are blocked in every profile.** They open network connections Sulayi's
  scope enforcement cannot constrain; the integrations are kept for when a verified
  outbound control exists.
- A `GET` endpoint that changes state is protected only if you list it in
  `assessment.stateChangingOperations`.

## Maturity

`v0.x`. Output schemas (`sulayi/v1alpha1`, `sulayi.report/v1alpha2`,
`sulayi.run/v1alpha1`, `sulayi.evidence/v1alpha1`, `sulayi.adapter/v1alpha1`) may change
before 1.0; each is versioned so a consumer can detect a change rather than misparse it.
Pre-1.0, only the latest release is supported.

## Install

```bash
go install github.com/jaylordibe/sulayi/cmd/sulayi@v0.1.0
sulayi version
```

Requires Go 1.27.4 or newer. Built and tested by CI on Linux, macOS and Windows.

Everything that changed is in the [changelog](../../CHANGELOG.md).
